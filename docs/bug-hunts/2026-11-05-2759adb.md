# Bug hunt: techautomator414/trailkeep @ 2759adb

## Confirmed bugs (1)

### 1. htmx 403 redirect doubles the context path (Low)

- **Where:** `src/main/java/io/trailkeep/security/HtmxAwareResponses.java`, `accessDenied()` → `redirect()` (L59-62) and `currentPath()` (L65-78).
- **Input:** The app is deployed under a servlet context path, e.g. `/app`. An htmx request is denied (for example because its CSRF token is stale) and carries `HX-Current-URL: https://host/app/cases/1`.
- **Expected:** `HX-Redirect: /app/cases/1`. The javadoc says it "reloads the page the user is on".
- **Actual:** `HX-Redirect: /app/app/cases/1`, which returns a 404. `currentPath` returns the raw path of the URL, and that path already includes the context path. `redirect` then puts `request.getContextPath()` in front of it a second time. With the default root context path (`""`) the result is correct, so only deployments with a context path are affected. That is why this is rated Low.
- **Failing test:** `/tmp/hunt/prover-3/T.java` is a standalone copy of the logic, not compiled against the project. It prints `current: /app/app/cases/1` and then `FAIL`.
- **Fix:** In `accessDenied`, use the path from `HX-Current-URL` as it is, without prepending the context path again. If that path does not start with `contextPath`, fall back to `contextPath + "/"`. For example:
  ```java
  String path = currentPath(request);
  String ctx = request.getContextPath();
  String target = (ctx.isEmpty() || path.equals(ctx) || path.startsWith(ctx + "/")) ? path : ctx + "/";
  response.setStatus(HttpServletResponse.SC_FORBIDDEN);
  response.setHeader("HX-Redirect", target);
  ```
  I checked this fix on the standalone copy. The reviewer also noticed that the query string is dropped, but the javadoc says that is deliberate, so it is not reported as a bug.

## Suspicions not checked (rated below 3, so never sent to a prover)

The readers and reviewers rated these 1 or 2. Some may still be real; they are the place to look next:
- `CaseSearchWriter.rebuild`: a null (purged) description is appended as the literal text `"null"`, so the case matches searches for "null".
- `CaseSearchWriter.rebuild`: comments are read through the user's scope, so the rebuilt search text can silently drop comments.
- `PrincipalCaseScope.toPredicate`: `notEqual(ownerId, userId)` excludes cases that have no owner.
- `LocalConfigSeed.run`: a seed name with leading or trailing whitespace may make startup fail with a CONFLICT on restart.
- `TeamAdminController.create`: ignores the form's `active` flag.
- `application.yml`: `max-request-size` is fixed at 26MB and does not follow `app.attachments.max-bytes`.
- `V3__admin.sql`: the SLA CHECK constraints don't enforce the upper bounds that the UI states.
- `DefaultCasePermissionService.roleOf`: for a COMPLIANCE_ADMIN who is also a team MANAGER, the global role hides the team role.
- `UserSignInServiceImpl`: role conflicts are kept only in memory, and memberships in inactive teams still count.
- `SessionJson`: a login time that fits in an int comes back as an Integer, which would end the session. This only happens with test clocks.
- Smaller items: a surrogate pair can be cut in half when the audit name is truncated, a `\r\n` counts as two characters in the description size check, the session lifetime check is off by one millisecond at the boundary, and the attachment size display rounds badly near 1 MiB.
